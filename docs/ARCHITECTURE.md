# 实现与取舍

## 从记录到脉络

一条记录拥有稳定 ID。`entries` 保存独立写作段落，每段有自己的创建时间、序号和 revision；修改前内容进入该段的 revisions。正文和配图是这些段落的投影。旧版本快照保存在 legacyVersions 中，避免把缺少时间依据的快照误判成一次新的续写。

服务端在 SQLite 事务内执行 create / append / edit / restore。客户端提供 operationId，重复提交相同操作不会重复生成段落。编辑检查 expectedRevision，遇到已发生的并发改动时拒绝覆盖。自定义名称使用原有元数据保存接口，更新前读取最新记录；接口合并元数据并拒绝过时的正文快照。

脉络保存在元数据中，只包含有序 noteIds。调整顺序不复制、合并或重写正文；同名记录也具有各自的 ID。导出脉络时按保存顺序读取成员，缺少成员或配图就报告失败。

## 同源服务

浏览器的相对 API 地址基于当前部署目录，支持 `/museknot/` 这样的子路径。一个 Node.js 进程同时服务前端构建产物和账号 API，SQLite 存储 users、sessions、notes、images、meta。每次读取或写入笔记都限定 user_id；客户端同时提交账号标识，降低跨标签页切换账号时误提交的风险。

浏览器本机检查点与云端草稿保存未提交输入，但正式内容只在提交成功后更新。恢复旧浏览器数据时先确认账号归属，迁移保留原始历史和图片。

## 长图与 PWA

长图渲染只读取已保存内容。文字按 grapheme 换行，完整文本行和图片作为分页块，避免分图时截断字符或图片。导出后释放临时对象 URL。不把未提交草稿或修改历史混进当前正文。

PWA 安装清单使用相对 start_url / scope 和独立窗口模式。Service Worker 不使用 CacheStorage：仅在应用根路径的导航请求无法联网时返回通用说明。当前页面不强制跳过等待、接管或刷新。这个选择简化隐私和更新行为，但不提供离线笔记阅读、编辑或冲突同步。

## 当前边界

- 服务端保存明文笔记、图片和备份，部署者负责访问限制与备份保护。
- 适合个人和小规模部署；敏感接口的限流状态保存在单进程内存中，重启会重置。
- 当前删除整条记录没有回收站，需要产品内确认；定期备份是独立保障。
- 首次正式开源提交整合了此前的实现，没有重建或伪造旧开发历史。
- 后续若扩展为多实例、大规模服务或完整离线同步，需要进一步设计限流、同步和数据生命周期。
